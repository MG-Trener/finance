# Refactor structure

Это переходная структура для отказа от временных `phase*.js` и `phase*.css` без риска сломать рабочую GitHub Pages версию.

## Целевая структура

- `src/js/core/` — Supabase, состояние, общие утилиты, загрузка данных;
- `src/js/features/` — функциональные модули: обзор, журнал, бюджеты, регулярные платежи, доступ, экспорт;
- `src/js/ui/` — навигация, модальные окна, подсказки, общие компоненты;
- `src/css/app.css` — единая точка входа стилей;
- `src/css/components/` — стили отдельных компонентов;
- `src/css/pages/` — стили страниц;
- `assets/` — изображения и UI-графика.

## Этап 1

1. `src/css/app.css` стал единой точкой подключения всех текущих стилей в прежнем порядке.
2. Новый функционал доступа супруги перенесён в `src/js/features/access-overview.js` и `src/css/components/access-overview.css`.
3. Старые `phase*.js/css` пока не удаляются: они будут переноситься по одному модулю после проверки поведения.

## Следующие шаги

1. Перенести авторизацию и загрузку данных из `app.js` в `src/js/core/`.
2. Перенести Обзор и форму операции в `src/js/features/overview.js`.
3. Перенести Журнал, Бюджеты, Регулярные платежи и Аналитику в отдельные feature-модули.
4. Слить CSS-фазы в страницы/компоненты, затем удалить `phase*.css`.
5. После стабилизации удалить старые Next.js/Prisma/Docker-файлы, которые не участвуют в GitHub Pages версии.
