# Android / APK

Проект собирается как Android-приложение через Capacitor. В APK веб-интерфейс находится локально в `www/`, поэтому для запуска приложения не требуется GitHub Pages.

## Что работает без интернета

После хотя бы одного успешного входа и синхронизации на устройстве сохраняется локальная копия семейных данных в IndexedDB.

Без сети доступны:

- просмотр ранее синхронизированных данных;
- добавление, изменение, удаление и восстановление финансовых операций;
- создание и последующая синхронизация переводов между супругами;
- изменение бюджетов;
- создание и изменение регулярных платежей;
- отметка регулярного платежа как оплаченного;
- создание финансовых целей и пополнений;
- архивирование и удаление целей;
- создание и переименование пользовательских категорий и подкатегорий.

Обычные локальные изменения попадают в основную очередь синхронизации. Новые переводы между супругами используют отдельную долговечную IndexedDB-очередь, потому что на сервере они создаются специальной RPC-функцией `create_family_transfer`. После восстановления соединения временная локальная запись заменяется серверной.

Если одна и та же обычная финансовая операция была изменена на другом устройстве, приложение останавливает автоматическую отправку этой записи и показывает конфликт с выбором: оставить серверную версию или отправить локальную.

## Мобильный интерфейс

Финальный мобильный слой `src/css/mobile-stability.css` загружается после старых адаптивных стилей и ограничивает потенциально опасные общие правила. Модальные окна классифицируются модулем `src/js/ui/modal-stability.js` как верхние task-modal, центрированные диалоги или нижние sheet. Благодаря этому редактирование операции, перевод и быстрое исправление суммы не зависят от случайного положения элемента в DOM.

Android-сборка дополнительно приводит системные status/navigation bars к тёмной теме приложения. Интерфейс заблокирован в портретной ориентации.

## Шрифты Android

Во время `mobile:prepare` сборщик получает Cinzel и Inter, сохраняет WOFF2-файлы локально в `www/assets/fonts/` и подключает локальный `mobile-fonts.css`. Поэтому установленному APK не требуется доступ к Google Fonts во время работы. Если внешний источник шрифтов временно недоступен именно в момент сборки, создаётся детерминированный системный fallback, и сборка не становится зависимой от сети при запуске приложения.

## Локальный PIN

В установленном APK/PWA можно включить шестизначный PIN через настройки защиты приложения. PIN хранится только на конкретном устройстве в виде PBKDF2-хэша и не заменяет Supabase Auth.

## Проверки перед выпуском

Draft/обычный pull request в `main` запускает UI regression tests, static integrity и полноценную Android-сборку. APK из pull request не публикуется как обновление. Rolling release создаётся только после попадания проверенных изменений в `main` и успешной Android-сборки.

Мобильные Playwright-тесты покрывают разные размеры Android viewport, создание расхода/дохода, смену супруга, редактирование, модальные режимы, навигацию, перевод, офлайн-перевод, читаемость типографики и компактность последних операций.

## Сборка и sideload-обновления

GitHub Actions workflow `.github/workflows/android-apk.yml` автоматически проверяет Android-проект в pull request и собирает APK после изменений интерфейса, Android-конфигурации или мобильных ресурсов.

Rolling `family-treasury.apk` использует стабильный специальный sideload/debug-ключ из `mobile-assets/debug-keystore.b64`. Этот ключ не является production-секретом и сохраняет совместимость обновлений с уже установленными тестовыми APK. `versionCode` увеличивается по номеру запуска GitHub Actions.

## Production signing

Workflow подготовлен и для отдельной постоянной production-подписи. Для неё нужно один раз создать release-keystore и сохранить его только в GitHub Actions Secrets:

- `ANDROID_KEYSTORE_BASE64`
- `ANDROID_KEYSTORE_PASSWORD`
- `ANDROID_KEY_ALIAS`
- `ANDROID_KEY_PASSWORD`

Если все четыре секрета настроены, workflow дополнительно выполняет `assembleRelease` и создаёт artifact `family-treasury-production-apk`. Release-keystore нельзя добавлять в публичный репозиторий: потеря или замена ключа лишит возможности устанавливать production-обновления поверх уже выпущенной production-версии.

До настройки этих секретов rolling sideload APK продолжает собираться стабильным существующим ключом, чтобы не нарушать обновление уже установленного приложения.

## Локальная сборка разработчиком

```bash
npm install
npm run mobile:prepare
npx cap add android
npx cap sync android
node scripts/configure-android-ui.mjs
cd android
./gradlew assembleDebug
```

Результат находится в `android/app/build/outputs/apk/debug/app-debug.apk`.
